Fix · 실패 지점을 나눠 확인

실행 위치는 HA 웹 화면입니다. 아래는 시행할 검사이며 실행 결과가 아닙니다. 실물 태그·조명·비콘 시험은 아직 하지 않았습니다.

  1. 개발자 도구 → 이벤트에서 tag_scanned 수신을 시작하고 휴대폰으로 태그를 읽습니다. tag_id, device_id가 나타나야 합니다.
  2. 이벤트가 없다면 NFC 활성화·잠금 해제·HA 앱 연결·금속 부착·쓰기 잠금을 확인합니다. 영구 잠금은 시험 완료 전 사용하지 않습니다.
  3. 이벤트는 있는데 알림이 없으면 자동화 추적에서 트리거와 조건을 확인하고 기존에 성공한 휴대폰 알림 동작을 선택합니다. 실제 서비스 이름을 새로 추측하지 않습니다.
  4. 조명은 개발자 도구 → 동작에서 light.turn_on에 실제 조명 엔티티를 선택해 수동 시험합니다. 수동 제어가 먼저 성공해야 NFC와 결합합니다.
  5. 중복 터치는 동일 기기·태그에 짧은 재실행 제한을 적용하고, ‘토글’보다 켜기·끄기를 명시해 중복 실행의 영향을 줄입니다.

로그 제안: 발생 시각, 태그 식별자, 스캔 기기, 선택 동작, 조건 판정, 자동화 추적 결과, 알림 수신 여부. ‘동작 호출 성공’과 ‘실제 수신’은 별도 기록합니다. 태그에 비밀번호·접근 토큰을 저장하지 않습니다.

비콘 감지 경로: 고정 iBeacon → Android Beacon Monitor → Companion 센서 → HA. G3에 USB 블루투스를 바로 추가하는 구성과 다릅니다. 휴대폰이 스캔하지 않거나 HA에 접속할 수 없으면 상태 반영이 지연됩니다. 보고된 거리는 추정값이며 실제 감지 속도·배터리 사용량을 측정해야 합니다.

전달할 요청문

이미 연결된 안드로이드와 시험 알림을 유지하고, 새 NFC 태그 하나로 시험 알림 자동화만 만들어줘. 태그 ID와 휴대폰 기기를 실제 이벤트에서 확인하고, 세 번 읽어 중복 없이 세 번 도착하는지 확인해줘. 성공 후 선택한 조명 하나만 연결하고 추적 결과를 알려줘. 기존 VirtualBox 자료와 세탁·건조기 전원은 변경하지 마.

08 · 운영 방식과 기록

현재는 G3 Windows의 기존 Docker Desktop 시험 환경에서 접속·로그인·대시보드·휴대폰 알림을 확인했습니다. 이것을 HAOS 복구 완료나 장기 운영 안정성 검증으로 확대하지 않습니다. 재부팅·절전·센서 연결·백업 복구는 각각 검증해야 합니다.

생활 화면은 상태·알림, 센서 화면은 마지막 진동·배터리·연결, 기록 화면은 감지 시각·종료 추정 이유·알림 시도·수신 확인을 구분해 구성할 계획입니다. 별도 DB 수집은 구현되지 않았습니다. HA 내부 DB에 새 표를 직접 추가하지 않습니다.

새 기기 연결 · 막히는 지점과 완료 증거

제품·구성참고 비용연동과 구매 판단

Tapo전구 제어와 센서 수신을 따로 시험앱 등록 후 TP-Link Smart Home 추가. 인증 실패 시 앱의 Tapo Lab → Third-Party Compatibility 확인. 기기 IP·같은 LAN 확인. 성공 증거: HA에서 수동 점등/소등 및 실제 움직임의 상태 이력.

첫 명령의 결과만 사용자 사진으로 확인했고 나머지는 실행 전입니다. 어댑터 이름·깨우기 지원 목록을 확인하며, 목록만으로 실제 S0 복귀 성공을 보장하지 않습니다. 로그를 공유할 때 계정·MAC·IP 등 개인 식별 정보는 가립니다.

기기 로그는 HA 설정 → 시스템 → 로그와 해당 통합의 진단을 확인합니다. 발생 시각·동작·기대 상태·실제 상태를 기록하고 토큰·계정·집 지도는 보고서에 넣지 않습니다.
