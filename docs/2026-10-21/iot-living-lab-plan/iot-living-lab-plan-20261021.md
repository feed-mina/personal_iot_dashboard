기준: 2026-10-21. 완료 기록 / 샘플 구현 / 실물 검증 전을 구분합니다.

## 01 · 기반 연결 — 완료 기록

**현재 상황** 기록상 G3 N100 Windows의 Home Assistant와 안드로이드 앱 연결, 시험 알림 수신이 확인됐습니다. 공개 샘플 대시보드와 포트폴리오 삽입도 완료했습니다.

**할 일** 기존 기기를 수동으로 시작하는 방식을 유지하고, 다음 실험 전 서버 접속과 시험 알림을 다시 확인합니다.

**부탁할 말** 센서 시험 전에 현재 접속과 휴대폰 알림부터 확인해줘.

**통과 기준** 접속 화면과 시험 수신 기록이 남으면 센서 단계로 갑니다.

**실패 대응** 접속 실패 시 먼저 연결을 복구합니다. 센서 문제와 섞지 않습니다.

## 02 · 모델·수신 — 다음 행동

**현재 상황** T1 출고 모델과 SLZB-06U 재고는 과거 문의 후 최종 확인 자료가 이 보고서에 없습니다. 구매·도착·연결 성공을 확정하지 않습니다.

**할 일** 출고 모델과 Zigbee 지원을 확인한 뒤 센서 1개를 연결합니다. 흔들림 이벤트, 마지막 수신, 배터리 표시를 각각 확인합니다.

**부탁할 말** 정확한 모델을 확인하고 흔들림이 기록되는지 함께 시험해줘.

**통과 기준** 부착 위치 사진과 모델·연결 방식·수신 기록이 남아야 합니다. 배터리 표시 지연과 이벤트 누락도 기록합니다.

**실패 대응** 수신이 안 되면 거리·배터리·연결을 점검합니다. 지원 목록에 있다는 사실만으로 우리 환경의 성공으로 간주하지 않습니다.

## 03 · 생활 관측 — 실험 예정

**현재 상황** 아직 실제 운전 기록이 없습니다. 센서 1개를 세탁기와 건조기에 번갈아 쓰면 동시 감시는 못 합니다.

**할 일** 기기·코스·부착 위치를 고정하고 평소 운전에서 시작, 중간 정지, 종료를 기록합니다. 옮길 때는 새 조건으로 구분합니다.

**부탁할 말** 진동 기록과 내가 확인한 운전 상태를 같은 회차에 정리해줘.

**통과 기준** 운전 중 멈춤과 종료가 함께 포함된 회차 기록이 있어야 합니다. 실제 종료를 보지 못했다면 종료 시각은 미상으로 둡니다.

**실패 대응** 진동이 약하면 위치를 바꿔 새 회차를 기록합니다. 이벤트 센서를 정밀 진동 파형 장비처럼 설명하지 않습니다.

## 04 · 추정·비교 — 이번 핵심

**현재 상황** 아직 모르는 것: 운전 중 정지와 종료를 구분할 수 있을까요? 확인: 같은 평가 기록으로 두 규칙을 비교합니다.

**할 일** 기준 방법은 일정 시간 이벤트가 없을 때 종료 후보를 만듭니다. 개선 방법은 충분한 작동 관측·기기별 조건·통신 이상 보류를 추가합니다. 조정용 회차와 최종 평가 회차를 나눕니다.

**부탁할 말** 기준 규칙과 개선 규칙의 오알림·놓친 종료·지연을 같은 회차로 비교해줘.

**통과 기준** 규칙을 평가 전에 고정하고 회차별 결과와 분모를 공개합니다. 제안한 예비 평가 목표는 기기별 5회이며, 통계적 성능 보장이 아닙니다. 횟수가 부족하면 예비 결과로만 표시합니다.

**실패 대응** 연결이 끊겼거나 상태가 오래되면 확인 필요로 보냅니다. 조용하다는 이유만으로 종료를 확정하지 않습니다. 오알림이 줄어도 놓침·지연이 늘면 함께 설명합니다.

## 05 · 알림·NFC — 실험 예정

**현재 상황** 휴대폰 시험 알림은 성공했지만 세탁 종료 추정에 따른 자동 알림은 아직 시험 전입니다. NFC 구매·연결도 확인 전입니다.

**할 일** 먼저 휴대폰 버튼으로 시작·종료 확인·아직 작동 중을 기록합니다. 필요할 때 NFC 태그로 같은 기록을 간편하게 남깁니다.

**부탁할 말** 추정 알림에 확인 버튼을 붙이고 발송·수신·사용자 확인 시각을 나눠 기록해줘.

**통과 기준** 한 회차에서 추정 → 발송 → 휴대폰 수신 확인 → 사용자 피드백을 연결합니다. 늦게 누른 확인 시각을 실제 종료 시각으로 바꾸지 않습니다.

**실패 대응** 중복 알림은 회차당 중복 방지 조건으로 점검합니다. 수신 확인이 없으면 발송 성공과 구분합니다.

## 06 · 결과·활용 — 계획

**현재 상황** 샘플 화면은 공개돼 있지만 실제 센서 성능 자료는 없습니다. 연구실 협업·입학·채용은 확정되지 않았습니다.

**할 일** 문제 정의 1쪽, 구성도, 실제 시연, 익명화 회차 표, 규칙 비교, 재현 방법과 한계를 묶습니다. 직접 만든 부분과 Home Assistant 제공 기능을 구분합니다.

**부탁할 말** 실험 결과를 연구 질문과 취업 역량에 연결한 사례 설명으로 정리해줘.

**통과 기준** 직접 구현·샘플·계획 태그와 근거 링크가 일치하면 포트폴리오를 갱신합니다. 평가 실패도 원인과 다음 실험으로 남깁니다.

**실패 대응** 한 집·소수 회차 결과를 모든 가전에 일반화하지 않습니다. 다음 센서 구매는 실제 누락·동시 감시 필요를 보고 결정합니다.

기준 방법

작동 관측 뒤 일정 시간 이벤트가 없으면 종료 후보로 판단합니다. 대기시간은 관측 기록으로 정하며 미리 성능을 보장하지 않습니다.



개선 방법

충분한 운전 관측, 기기별 설정, 중간 정지 조건, 통신 이상 보류를 더합니다. 평가 전에 조건을 고정합니다.

평가표: 전체 운전 횟수 / 알림 수 / 잘못 보낸 알림 수 / 놓친 종료 수 / 종료 시각을 직접 확인한 회차의 알림 지연. 분모와 미확인·제외 회차를 함께 적습니다. 최종 평가 중 규칙을 고쳤다면 새 버전의 새 평가로 구분합니다.

별도 상태 보고가 없는 이벤트 센서에서는 이벤트가 없다는 것만으로 연결 정상·연결 끊김을 확정할 수 없습니다. 연결 상태를 확인할 수 없는 구간은 판단 보류로 처리하는 보수적 방법도 함께 비교합니다.

안전·개인정보·운영 원칙

세탁기·건조기는 수동 시작을 유지합니다. 전원 회로 개조·안전 장치 우회는 실험에 포함하지 않습니다. 공개 자료에는 집 주소·내부 접속 주소·계정·인증정보·원본 생활 시간표를 넣지 않습니다. 원본은 로컬에 두고 외부 공유는 기기 별칭·상대 시간으로 바꿉니다. 수집 항목과 보관·삭제 기준을 실험 전에 정합니다.

기존 VirtualBox VDI와 백업은 보존합니다. Home Assistant OS와 Container는 설치·확장 기능 운영 방식이 다르므로 현재 설치를 먼저 확인하고 안내를 맞춥니다. 이번 작업은 보고서 갱신이며 설치 전환이나 설정 변경을 수행하지 않았습니다.
