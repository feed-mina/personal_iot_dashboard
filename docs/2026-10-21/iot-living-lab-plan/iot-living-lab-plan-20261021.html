완료 기록

현재 상황

기록상 G3 N100 Windows의 Home Assistant와 안드로이드 앱 연결, 시험 알림 수신이 확인됐습니다. 공개 샘플 대시보드와 포트폴리오 삽입도 완료했습니다.

내가 할 일

기존 기기를 수동으로 시작하는 방식을 유지하고, 다음 실험 전 서버 접속과 시험 알림을 다시 확인합니다.

센서가 실제로 알려주는지

다음 행동

현재 상황

T1 출고 모델과 SLZB-06U 재고는 과거 문의 후 최종 확인 자료가 이 보고서에 없습니다. 구매·도착·연결 성공을 확정하지 않습니다.

내가 할 일

출고 모델과 Zigbee 지원을 확인한 뒤 센서 1개를 연결합니다. 흔들림 이벤트, 마지막 수신, 배터리 표시를 각각 확인합니다.

도우미에게 부탁할 말

정확한 모델을 확인하고 흔들림이 기록되는지 함께 시험해줘.

끝났는지 확인하는 법

부착 위치 사진과 모델·연결 방식·수신 기록이 남아야 합니다. 배터리 표시 지연과 이벤트 누락도 기록합니다.

실패하면

수신이 안 되면 거리·배터리·연결을 점검합니다. 지원 목록에 있다는 사실만으로 우리 환경의 성공으로 간주하지 않습니다.

실제 운전과 잠깐 멈춤을 기록

실험 예정

현재 상황

아직 실제 운전 기록이 없습니다. 센서 1개를 세탁기와 건조기에 번갈아 쓰면 동시 감시는 못 합니다.

내가 할 일

기기·코스·부착 위치를 고정하고 평소 운전에서 시작, 중간 정지, 종료를 기록합니다. 옮길 때는 새 조건으로 구분합니다.

도우미에게 부탁할 말

진동 기록과 내가 확인한 운전 상태를 같은 회차에 정리해줘.

끝났는지 확인하는 법

운전 중 멈춤과 종료가 함께 포함된 회차 기록이 있어야 합니다. 실제 종료를 보지 못했다면 종료 시각은 미상으로 둡니다.

실패하면

진동이 약하면 위치를 바꿔 새 회차를 기록합니다. 이벤트 센서를 정밀 진동 파형 장비처럼 설명하지 않습니다.

생활 실험실 / 첫 프로젝트 / 04 · 추정·비교

단순 규칙부터 개선 규칙까지

이번 핵심

현재 상황

아직 모르는 것: 운전 중 정지와 종료를 구분할 수 있을까요? 확인: 같은 평가 기록으로 두 규칙을 비교합니다.

내가 할 일

기준 방법은 일정 시간 이벤트가 없을 때 종료 후보를 만듭니다. 개선 방법은 충분한 작동 관측·기기별 조건·통신 이상 보류를 추가합니다. 조정용 회차와 최종 평가 회차를 나눕니다.

도우미에게 부탁할 말

기준 규칙과 개선 규칙의 오알림·놓친 종료·지연을 같은 회차로 비교해줘.

끝났는지 확인하는 법

규칙을 평가 전에 고정하고 회차별 결과와 분모를 공개합니다. 제안한 예비 평가 목표는 기기별 5회이며, 통계적 성능 보장이 아닙니다. 횟수가 부족하면 예비 결과로만 표시합니다.

실패하면

연결이 끊겼거나 상태가 오래되면 확인 필요로 보냅니다. 조용하다는 이유만으로 종료를 확정하지 않습니다. 오알림이 줄어도 놓침·지연이 늘면 함께 설명합니다.

생활 실험실 / 첫 프로젝트 / 05 · 알림·NFC

사람이 마지막 확인을 남기기

실험 예정

현재 상황

휴대폰 시험 알림은 성공했지만 세탁 종료 추정에 따른 자동 알림은 아직 시험 전입니다. NFC 구매·연결도 확인 전입니다.

내가 할 일

먼저 휴대폰 버튼으로 시작·종료 확인·아직 작동 중을 기록합니다. 필요할 때 NFC 태그로 같은 기록을 간편하게 남깁니다.

도우미에게 부탁할 말

추정 알림에 확인 버튼을 붙이고 발송·수신·사용자 확인 시각을 나눠 기록해줘.

끝났는지 확인하는 법

한 회차에서 추정 → 발송 → 휴대폰 수신 확인 → 사용자 피드백을 연결합니다. 늦게 누른 확인 시각을 실제 종료 시각으로 바꾸지 않습니다.

실패하면

중복 알림은 회차당 중복 방지 조건으로 점검합니다. 수신 확인이 없으면 발송 성공과 구분합니다.

연구·취업에 보여줄 증거 만들기

계획

현재 상황

샘플 화면은 공개돼 있지만 실제 센서 성능 자료는 없습니다. 연구실 협업·입학·채용은 확정되지 않았습니다.

내가 할 일

문제 정의 1쪽, 구성도, 실제 시연, 익명화 회차 표, 규칙 비교, 재현 방법과 한계를 묶습니다. 직접 만든 부분과 Home Assistant 제공 기능을 구분합니다.

도우미에게 부탁할 말

실험 결과를 연구 질문과 취업 역량에 연결한 사례 설명으로 정리해줘.

끝났는지 확인하는 법

직접 구현·샘플·계획 태그와 근거 링크가 일치하면 포트폴리오를 갱신합니다. 평가 실패도 원인과 다음 실험으로 남깁니다.

실패하면

한 집·소수 회차 결과를 모든 가전에 일반화하지 않습니다. 다음 센서 구매는 실제 누락·동시 감시 필요를 보고 결정합니다.

기준 방법

작동 관측 뒤 일정 시간 이벤트가 없으면 종료 후보로 판단합니다. 대기시간은 관측 기록으로 정하며 미리 성능을 보장하지 않습니다.

개선 방법

충분한 운전 관측, 기기별 설정, 중간 정지 조건, 통신 이상 보류를 더합니다. 평가 전에 조건을 고정합니다.

평가표: 전체 운전 횟수 / 알림 수 / 잘못 보낸 알림 수 / 놓친 종료 수 / 종료 시각을 직접 확인한 회차의 알림 지연. 분모와 미확인·제외 회차를 함께 적습니다. 최종 평가 중 규칙을 고쳤다면 새 버전의 새 평가로 구분합니다.

별도 상태 보고가 없는 이벤트 센서에서는 이벤트가 없다는 것만으로 연결 정상·연결 끊김을 확정할 수 없습니다. 연결 상태를 확인할 수 없는 구간은 판단 보류로 처리하는 보수적 방법도 함께 비교합니다.

서울대 연구와 어떻게 연결할까?

아래는 공식 연구 방향을 참고한 프로젝트 적합성 제안입니다. 연구실 협업·입학·연구 참여가 확정됐다는 의미가 아닙니다.

공식 연구 방향이 프로젝트와의 연결 제안준비할 결과물
서울대 HAI Lab · 지능형 계측·시스템 모델링·의사결정관측 → 상태 추정 → 오류 분석의 실험 설계중간 정지 오인 사례, 기준 규칙과 개선 규칙 비교
서울대 AIoT Lab · 적응형 센싱·Physical AI 관련 발표적은 센서로 얻는 정보의 한계와 비용·성능의 균형위치·기기·감도별 기록, 통신 누락과 추정 실패
서울대 휴먼인터페이스 연구실 · 음성·음향·대형 언어 모델후속 단계: 현재 상태를 조회하고 근거를 설명하는 생활 비서센서 조회와 설명서 검색을 분리한 대화 예시·사용자 확인 흐름

첫 결과물은 HAI·AIoT 방향에 더 직접적으로 연결됩니다. 시흥캠퍼스와의 거리만으로 연구실 소속·위치·지원 과정을 추정하지 않습니다. FMTC·모빌리티 연결은 로봇 관제 경험이 쌓인 뒤 검토할 후속 주제로 둡니다.

제조·IoT 취업에서는 무엇을 보여줄까?

보여줄 역량직접 준비할 증거포트폴리오에서 쓸 표현
제조·IoT 데이터 수집이벤트 수신·시각·연결 상태와 누락 사례기존 가전의 진동 이벤트 수집과 상태 기록을 구성했다
판단·오류 대응규칙 버전별 비교와 통신 이상 보류 사례종료를 확정하지 않고 추정 근거와 확인 필요 상태를 설계했다
분석·대시보드실측 회차별 근거와 계산 분모, 샘플/실측 전환 표기샘플 UI를 구현했고 실측 성능은 별도 평가했다 — 평가 후 사용
에이전트·사람 확인기록 조회 → 설명 → 허용된 알림 → 결과 기록데이터 수집 → 판단 → 확인 → 실행 → 검증 흐름을 구현했다 — 구현 후 사용

위 연결은 역량을 설명하는 제안이며 특정 채용공고의 요건 충족이나 합격을 보장하지 않습니다. 실제 지원 때는 공고별 필수 역량과 내 증거를 다시 맞춥니다.

집: 센서 → 판단 → 확인 → 알림 → 결과 기록

최종 결과물 묶음

  1. 문제 정의 1쪽: 기존 가전을 유지한 이유와 놓치는 생활 알림 문제
  2. 구성도와 실제 시연: 센서부터 휴대폰 수신·사용자 확인까지
  3. 익명화 회차 데이터: 정상·오판·통신 이상을 함께 포함
  4. 비교 보고서: 기준/개선 규칙의 분모·오알림·놓침·지연
  5. 재현 안내: 기기·센서 위치·버전·시험 조건·알려진 한계

각 결과에는 직접 구현 / 제공 기능 활용 / 샘플 / 계획과 공개 가능 / 비식별 필요 / 비공개를 붙입니다. 현 단계의 정직한 소개: “샘플 대시보드를 공개하고 휴대폰 시험 알림을 확인했으며, 센서 기반 종료 추정 실험을 준비하고 있습니다.”

안전·개인정보·운영 원칙

세탁기·건조기는 수동 시작을 유지합니다. 전원 회로 개조·안전 장치 우회는 실험에 포함하지 않습니다. 공개 자료에는 집 주소·내부 접속 주소·계정·인증정보·원본 생활 시간표를 넣지 않습니다. 원본은 로컬에 두고 외부 공유는 기기 별칭·상대 시간으로 바꿉니다. 수집 항목과 보관·삭제 기준을 실험 전에 정합니다.

기존 VirtualBox VDI와 백업은 보존합니다. Home Assistant OS와 Container는 설치·확장 기능 운영 방식이 다르므로 현재 설치를 먼저 확인하고 안내를 맞춥니다. 이번 작업은 보고서 갱신이며 설치 전환이나 설정 변경을 수행하지 않았습니다.
